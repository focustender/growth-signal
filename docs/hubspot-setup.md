# HubSpot — configuration and seeding log

## The tooling gap, and why the seeding path looks the way it does

The HubSpot MCP connector's OAuth scopes correctly grant Contact/Company/Deal read-write access, but the actual tool surface exposed to Claude has no generic create-or-update-CRM-object tool — only narrowly scoped write tools for campaigns, landing pages, and AEO content. This looks like a deliberate guardrail against AI agents bulk-writing CRM data directly, not a misconfiguration. Worth noting as-is rather than working around it silently: it shaped the actual seeding approach below.

## Seeding approach

750 contacts — a stratified sample of the same customers already analyzed in `data/customers.csv` / `data/trade_signal.db`, not a disconnected fake set — generated by `data/generate_hubspot_import.py` and imported through HubSpot's own native Contacts → Import CSV flow (a standard user-facing feature, not custom development).

Sample size: 750 of 3,200, chosen deliberately below the account's 1,000-contact limit to leave headroom for a corrective re-import or later additions, rather than filling the account to capacity on the first pass. Segments kept proportional to the full population:

| Segment | Target | Actual (live-verified) |
|---|---|---|
| Homeowner | 412 | 412 |
| Designer | 150 | 150 |
| Trade | 135 | 135 |
| Commercial | 53 | 53 |

Names are fabricated for realism; every email uses the `@example.com` domain, reserved under RFC 2606 for documentation and testing and guaranteed to never reach a real inbox — this is a real, live HubSpot account, so nothing in it should be capable of accidentally emailing an actual person.

## Custom properties created during import

- `trade_signal_segment` (dropdown/enumeration) — homeowner, designer, trade, commercial
- `trade_signal_source_channel` (dropdown/enumeration) — the 8 acquisition channels from the funnel model
- `trade_signal_region` (text)
- `trade_signal_signup_date` (date)
- `trade_signal_customer_id` (text) — the join key back to the SQLite dataset, so any HubSpot record can be traced back to its full funnel history

## Verification

Read back live through the connector, not assumed from the import summary: querying `trade_signal_segment` by exact value returns 412/150/135/53 respectively, matching the generation targets exactly. One spot-checked record (CUST-01752, Nancy Wright) confirmed all five custom properties present with correct values.

## What's still SQLite, deliberately

The full-population funnel analysis and the 73% trade-show-stall finding in `docs/measurement-foundation.md` are sourced from the complete 3,200-customer SQLite dataset, not the 750-record HubSpot sample — a quarter-scale sample is a reasonable live-CRM proof point, not a substitute for analyzing the whole population.
